    auto_track.scanning — Detektoren, Kamera und PTZ-Steuerung.

    auto_track.scanning.HogHumanDetector ¶

    Klassischer OpenCV-HOG-Personendetektor (kein Neuronales Netz).

    Identisch zum Ansatz im Repo 'ITCoders/Human-detection-and-Tracking': cv2.HOGDescriptor mit dem eingebauten 'getDefaultPeopleDetector' (default TracPlus). Es werden keine Boxen nachgeschätzt, daher platzt/pulsiert die Box nicht. Zusaetzlich wird eine EMA-Glaettung angewendet, damit der Kasten ruhig und stabil bleibt.

    Detektion laeuft auf der halbierten Aufloesung (rasch), die Boxen werden zurueck auf die Originalgroesse skaliert.

    auto_track.scanning.OpenVinoHumanDetector ¶

    OpenVINO-beschleunigter CrowdHuman-Personendetektor.

    Nutzt dasselbe jahongir-Modell, aber als nach OpenVINO IR exportiertes (gefrrorenes) Netz mit fester, quadratischer 416x416-Letterbox. Der Input ist damit deterministisch und der IR-Output (1,5,3549) statisch -> gut geeignet fuer CPU/GPU-Beschleunigung ohne Dynamik-Shape-Probleme. Ausgabe identisch strukturiert wie JahongirHumanDetector.

    auto_track.scanning.CgiPtzController ¶

    PTZ-Steuerung der Hi3510-UtutCam ueber imperativische CGI-Schritte.

    Jeder Aufruf von yt{up,down,left,right}.cgi dreht die Kamera um einen festen, kleinen Schritt und stoppt von selbst (kein Stop noetig). Parameter wie speed/step werden von der Kamera ignoriert.

    Thread-sicher. Mit Rate-Limit, damit die Kamera nicht ueberlastet wird.

    auto_track.scanning.PTZController ¶

    ONVIF-PTZ-Controller via onvif-zeep.

    Nutzt create_type('ContinuousMove') (statt roher SOAP) — das ist der entscheidende Baustein, der die Ginatex-Kamera dazu bringt, Befehle zu akzeptieren. Jedes Move trägt Timeout (Dead-man's switch).

    __init__() ¶

    left(speed=SCAN_SPEED) ¶

    move_velocity(pan, tilt, timeout=_PTZ_MOVE_TIMEOUT) ¶

    Kontinuierliche Proportionalbewegung, Werte in [-1, 1].

    pan/tilt werden auf sinnvolle Grenzen geklemmt. Der Timeout ist der Dead-man's switch der Kamera.
